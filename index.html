Система управления с ИИ для «Натурпласта»

Тестовое задание к вакансии «Архитектор корпоративной AI-платформы». Александр Костюхов, @xanderexe, 27.10.2026

1. Два ориентира

А. Система управления на ИИ-агентах в компании с брендами на Amazon личный опыт, внедрение

Что делала. Связка вокруг денег и продаж небольшой e-commerce-компании: сервис платежей с планом и фактом вместо Excel финотдела, панель сводки для владельца, кабинет партнёров со своими правами, дашборд аналитики, дежурный агент, который сам поднимал тревогу по сбоям, и агент-координатор, который читал задачи и переписку команды в трекере и раздавал работу.

Роль ИИ. Не «чат, который отвечает на вопросы», а ведение цикла: заметил отклонение → собрал причину → предложил варианты с ценой каждого → человек выбрал → задача исполнителю → проверка по следу в данных, а не по слову «сделал».

Что перенять. Решение руководителя как отдельная карточка с вариантами и рекомендацией, выбор одной кнопкой. Контроль исполнения по данным. Одна точка входа для руководителя вместо пяти дашбордов.

Ограничения. Собрано под одну компанию, без готовой BI-платформы. Дольше всего заняли не интеграции, а сверка цифр с тем, что финотдел считал у себя.

Скриншоты интерфейсов под NDA — работу такой системы покажу на созвоне. Ниже — схема цикла, по которому она работала.

Б. Yandex DataLens с Нейроаналитиком документация и демонстрация продукта

Что делает. BI-платформа: подключает источники (в том числе Битрикс24 и базы, куда выгружаются 1С и маркетплейсы), строит дашборды и права доступа. Нейроаналитик по вопросу обычными словами находит данные, строит график и пишет вывод; с обновления июня 2026 есть виджет на дашборде — инструкция словами, и при каждом открытии он показывает актуальный статус, с учётом прав пользователя.

Что перенять. Не писать дашборды и права с нуля. Виджет «статус по инструкции» — готовая утренняя сводка руководителя.

Ограничения. Показывает и объясняет, но задачи не ставит и исполнение не проверяет — цикл управления в нём не замыкается. 1С и WB/Ozon сначала нужно выгрузить в хранилище. Часть функций — в бете.

Как связаны процессы управления

2. Вариант для «Натурпласта»

Коротко: готовая BI для витрины, свой ИИ-агент «аналитик-диспетчер» для цикла «нашёл → предложил → согласовали → сделали → проверили», задачи остаются в Битрикс24, где команда уже работает.

Что взять готовым, что связать, что доработать

  • Готовое: 1С (себестоимость, расходы), Битрикс24 (задачи, CRM, сроки), DataLens для дашбордов и прав, языковая модель через API.
  • Связать: хранилище, куда раз в сутки (по продажам — чаще) приходят выгрузка 1С, API Wildberries и Ozon (продажи, остатки, реклама, комиссии) и задачи Битрикс24. Сервис аналитики маркетплейсов — как источник цен конкурентов.
  • Доработать: справочник «SKU → себестоимость → маржа после рекламы и комиссий», правила порогов и агента, который каждое утро сверяет показатели с планом, ищет причину, предлагает 2–3 решения с прогнозом, после согласования ставит задачу и через срок проверяет результат.

Кто как пользуется

  • Руководитель: утром одна сводка в Битрикс24 или Телеграме — главные отклонения с причиной и вариантами, кнопка «согласовать». Дашборд DataLens — когда нужно копнуть глубже.
  • Сотрудники: обычная задача в Битрикс24 с контекстом, сроком и условием, по которому её примут.
  • Финансист: подтверждает себестоимость и видит расхождения с 1С — без этого цифрам никто не поверит.

Сценарий

  1. Обнаружила: по товару на Ozon маржа после рекламы за неделю ушла в минус.
  2. Причина и варианты: ставки в автокампании выросли, конкурент снизил цену, выкуп просел. Варианты: снизить ставку, поднять цену, остановить рекламу по этому SKU — у каждого прогноз маржи и остатка на две недели, рекомендован первый.
  3. Согласовал: руководитель выбрал «снизить ставку» одной кнопкой.
  4. Выполнено: задача менеджеру Ozon в Битрикс24 со сроком «сегодня», менеджер закрыл её.
  5. Проверено: через три дня агент смотрит ДРР и маржу по данным. Вернулось в плюс — карточка закрыта, итог в недельный отчёт. Нет — новая карточка со следующим вариантом.

Первый пилот — 4 недели

Что проверяем: одна площадка (Ozon или WB) и главные по выручке SKU; ежедневная сводка по марже после рекламы и остаткам и полный цикл с задачами в Битрикс24.

Как оцениваем пользу: маржа в системе сходится с расчётом финансиста; часть отклонений система находит раньше команды; руководитель согласует большинство предложений без переделки; по закрытым карточкам видно, сколько денег вернули.

Главный риск: себестоимость и расходы в 1С не разнесены по SKU — тогда маржа неверная, и доверие к системе теряется в первую неделю. Поэтому пилот начинается со сверки маржи с финансистом.

Вопросы, без которых дальше нельзя:

  1. Где сейчас считается маржа по SKU и чьей цифре верят?
  2. Какие решения руководитель принимает каждую неделю и на какие цифры смотрит?
  3. Кто даст доступы к API WB и Ozon и выгрузку из 1С?
  4. Какой сервис аналитики уже используете и считаете эталоном?
